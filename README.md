# Fear & Greed 아침 알림봇

미국 지수투자를 하며 매일 확인하던 CNN Fear & Greed Index와 주요 시장 데이터를 모아, 아침에 Telegram 메시지 하나로 받아보기 위해 만든 Python 봇입니다.

## 왜 만들었나

미국 지수투자를 할 때 시장 참여자들의 심리를 살펴보는 것이 중요하다고 생각해 CNN Fear & Greed Index를 꾸준히 확인했습니다. 여기에 환율과 주요 지수까지 함께 확인하는 일을 매일 반복하다 보니, 직접 찾아보는 과정을 자동화하고 싶었습니다.

목표는 **아침마다 같은 항목을 같은 형식으로 받아보는 것**이었습니다. 시장심리 지표와 가격 정보를 모으는 일은 봇이 담당하고, 그 정보를 투자 판단에 어떻게 활용할지는 제가 결정하도록 만들었습니다. 다만 코드에는 제가 정해 둔 ISA 매수 규칙(매월 1일 정기 매수, 극단적 공포 2·3단계 진입 시 추가 매수 고려)을 알려 주는 문구도 들어 있습니다. 이 규칙의 한계는 아래 [한계와 다음 개선](#한계와-다음-개선)에 적었습니다.

처음 GitHub에 올린 날은 2026-07-09이고, 7-14에 발송 요청 인증을 추가했습니다. 이 저장소는 개인정보를 정리하려고 2026-09-13에 새 이력으로 다시 올린 공개본이라 그 이전 커밋은 들어 있지 않습니다. 이후 구성 지표 설명을 더한 확장판은 [fng-chatbot-mcp-deepseek](https://github.com/0gnm0-afk/fng-chatbot-mcp-deepseek)입니다.

## 무엇을 자동화했나

### Google Cloud에서 아침 알림 받기

실제 알림 서비스는 **Google Cloud Run**에서 실행하고, **Cloud Scheduler**가 정해진 아침 시각에 호출하는 방식으로 운영합니다. 개인 컴퓨터를 켜두지 않아도 클라우드에서 데이터를 수집하고 Telegram으로 알림을 보낼 수 있도록 구성했습니다.

```text
Cloud Scheduler: 아침 예약 호출
    → Cloud Run: 봇 실행·데이터 수집·메시지 구성
    → Telegram: 휴대전화로 알림 수신
```

다만 실제 Cloud Run 배포본과 이 저장소의 공개 코드는 동일하지 않습니다. 아래 기능과 실행 안내는 공개 코드 기준이며, Cloud Run 배포 설정과 Scheduler 예약 설정은 별도로 구성해야 합니다. 이 저장소를 복제하는 것만으로 현재 운영 환경 전체가 재현되지는 않습니다.

### 공개 코드가 처리하는 과정

외부에서 인증된 발송 요청을 받으면 다음 과정을 실행합니다.

```text
아침 예약 호출 → 발송 요청 인증 → F&G·시장 데이터 수집
             → 구간·등락률 계산 → 메시지 구성 → Telegram 발송
```

| 확인할 정보 | 자동으로 처리하는 내용 |
|---|---|
| CNN Fear & Greed Index | 점수를 가져와 정수로 반올림하고, 코드에 정의한 심리 구간과 이전 구간 대비 변화를 표시 |
| 원/달러·비트코인/달러 | 가격과 등락률을 조회·계산 |
| 코스피·나스닥·S&P500 | 지수와 등락률을 수집해 한 묶음으로 표시 |
| 나스닥 선물·S&P500 선물 | 조회된 가격과 등락률을 별도 묶음으로 표시 |

웹에서 확인하던 금융 데이터를 자동으로 가져와 메시지로 정리합니다. CNN F&G와 코스피는 CNN·네이버 금융의 웹 데이터 주소에 직접 요청해 JSON 응답에서 필요한 값을 읽습니다. 나머지 시장 데이터 6종은 기존 오픈소스 라이브러리인 FinanceDataReader의 조회 기능을 사용합니다.

직접 구현한 부분은 이 조회들을 연결하고, F&G 구간을 분류하고, 가격 등락률을 계산해 Telegram 메시지로 보내는 흐름입니다. FinanceDataReader를 통한 6종의 등락률은 최근 14일 조회 결과에서 마지막 두 유효한 종가를 비교해 계산합니다.

일부 시장 데이터 조회가 실패하면 해당 항목을 생략하고 수집된 항목으로 메시지를 구성합니다. 코스피 투자자별 순매수도 추가 조회하는 코드가 있으나, 응답 필드의 단위 검증은 후속 과제로 남아 있습니다.

## 실제로 받는 메시지

아래는 실제 운영 서비스에서 수신한 메시지 예시입니다. 공개 코드를 실행해 새로 생성한 검증 결과는 아닙니다. 수신 일시는 별도로 기록하지 않았으며, 현재 시세를 뜻하지 않습니다. 제목의 영문 철자만 정리했습니다.

```text
Fear & Greed 알림봇
📊 오늘의 F&G 지수: 29
(현재 상태: Fear 구간)

--- 🌏 주요 시장 현황 (전일 대비) ---
· 💹 원/달러: 1,363.60 (+1.34%) 원
· 🪙 비트코인/달러 : $75,873.92 (-2.93%)

전일 종가
· 🇰🇷 코스피: 6,627.26 (-0.85%)
· 🇺🇸 나스닥: 25,981.57 (-0.78%)
· 🇺🇸 S&P500: 7,585.73 (-0.45%)

현재 선물
· 🇺🇸 나스닥 선물 : 29,283.25 (+0.45%)
· 🇺🇸 S&P500 선물 : 7,664.00 (+0.51%)
```

이 메시지로 시장심리 구간과 주요 시장 가격을 함께 확인합니다. 다만 현재 출력의 “전일 종가”·“현재 선물”이라는 제목은 각 데이터의 기준 시각을 검증한 표시가 아닙니다. 특히 선물은 실시간 호가를 보장하지 않습니다.

## 왜 이 도구들을 사용했나

| 도구 | 맡긴 역할과 이유 |
|---|---|
| Python·requests·FinanceDataReader | 반복되는 데이터 조회와 수치 계산을 코드로 고정 |
| Flask | 외부 스케줄러가 호출할 발송 경로와 상태 확인 경로 제공 |
| Google Cloud Run | 개인 컴퓨터를 켜두지 않고 봇을 실행하는 운영 환경 |
| Google Cloud Scheduler | 데이터 처리 코드와 분리해 아침 실행 시각 관리 |
| Telegram Bot API | 휴대전화에서 확인할 수 있는 메시지로 전달 |

이 저장소의 공개 코드는 입력 데이터와 출력 형식이 정해진 작업을 LLM 없이 규칙 기반으로 처리합니다. 공개 코드에는 데이터베이스도 사용하지 않습니다.

## 현재 결과와 검증 범위

직접 지표를 찾아보던 작업을 아침 메시지 수신 흐름으로 바꾸어 사용하고 있습니다. 위 예시는 실제 수신 결과이며, 시간 절감량·장기 발송 성공률·투자 수익 개선은 별도로 측정하지 않았습니다.

자동 테스트는 Flask 요청을 통해 상태 확인, 발송 인증, 설정 누락, Telegram 실패 응답, 반복·동시 요청 제한, Telegram 오류의 민감정보 노출 방지를 검사합니다. 외부 데이터 조회와 Telegram 전송은 모의 응답으로 대체하므로 실제 데이터 정확도나 예약 운영 성공을 검증하는 테스트는 아닙니다.

```bash
python -m unittest discover -s tests -v
```

## 한계와 다음 개선

- **데이터 시점과 누락 표시:** 항목별 기준 시각이 없고, 실패한 시장 항목은 생략됩니다. 다음에는 기준 시각과 수집 실패를 메시지에 명시하려 합니다.
- **F&G 입력 검증:** 현재 점수 필드가 누락되면 기본값 0을 사용하며, 이전 종가가 없으면 일주일 전 점수를 비교에 사용합니다. 결측과 비교 기간을 명시하도록 보완해야 합니다.
- **개인 매수 알림 규칙:** 코드에는 월초 및 극단 구간 단계 진입에 따른 개인용 알림 문구도 있습니다. 현재 극단적 공포와 탐욕이 같은 단계 값을 공유해 공포용 추가 매수 알림이 탐욕 구간에서도 나올 수 있습니다. 검증된 매수 신호로 사용할 수 없으며, 조건 분리와 테스트가 필요합니다. 주문 실행 기능은 없습니다.
- **발송 기록:** 프로세스 내부의 동시 발송 제한과 60초 간격 제한은 있지만, 재시작·여러 인스턴스·응답 유실 상황에서 중복 발송을 완전히 막지는 못합니다. 장기 운영을 검증하려면 발송 이력과 실패 기록을 축적해야 합니다.

## 실행과 예약 연결

```bash
pip install -r requirements.txt
python main.py
```

실행 전에 다음 환경변수를 설정합니다. `.env.example`은 설정 예시이며 실제 값은 저장소에 기록하지 않습니다.

| 환경변수 | 용도 |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Telegram 봇 인증 |
| `TELEGRAM_CHAT_ID` | 메시지를 받을 채팅 또는 채널 |
| `JOB_TOKEN` | 발송 요청 인증용 32자 이상 임의 문자열 |
| `PORT` | 서버 포트, 미설정 시 8080 |

`JOB_TOKEN` 생성 예시:

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

외부 스케줄러가 원하는 아침 시각에 아래 요청을 보내도록 설정합니다. 다음은 셸 호출 예시입니다.

```bash
curl -fsS -X POST \
  -H "X-JOB-TOKEN: $JOB_TOKEN" \
  https://example.com/send
```

- `GET /`, `GET /healthz`: 상태 확인만 수행합니다.
- `POST /send`: 인증된 요청에 대해서만 수집과 발송을 수행합니다.
- 서버 환경변수와 스케줄러 헤더에 같은 `JOB_TOKEN`을 설정합니다. 토큰은 URL 쿼리 문자열에 넣지 않습니다.
- 기존 GET `/` 예약은 POST `/send`로 변경해야 합니다. Cloud Run IAM 인증을 사용한다면 Scheduler의 OIDC 설정도 유지합니다. IAM 인증과 `JOB_TOKEN`은 별개입니다.
- 반복·동시 요청은 429와 `Retry-After`를 반환합니다. 성공 여부와 관계없이 발송 시도 간 60초를 둡니다.

배포용 `Procfile`은 Gunicorn으로 Flask 앱을 실행합니다. 예약 주기·시간대·배포 서비스 설정은 별도로 구성해야 합니다.
